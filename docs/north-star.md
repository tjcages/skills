# Skills monorepo — North Star

**Version:** 0.1 · Tool / methodology library · 2026-07-21

> Answers extracted from existing `README.md` + `KICKOFF.md` doctrine — not invented mid-session.

## Pitch

A monorepo of **methodology-first Agent Skills** — extracted from real builds (especially Socials/Obi), dogfooded on independent targets, then packaged for agents.

## Who for

Builders and agents (Cursor / Claude Code) who need reusable *judgment frames* — not one-off prompt dumps — for Linear discipline, worktrees, constitutions, accept-gated AI, lossless migration, and behavior contracts.

## Non-negotiables

1. **Methodology > mechanics** — teach judgment; scripts are optional helpers.
2. **Dogfood before ✅ v1** — two independent targets; v0.x is draft, not done.
3. **Linear is source of truth** for non-trivial pack work (team Off-brand · project extracted-skills).
4. **One folder per pack** — mirror `linear-methodology/` layout (`shared/` + `skills/`).
5. **Socials is reference only** — never land skill source of truth back into Socials.

## Out of scope

- Shipping Socials / Tasks product UI under this repo’s name
- Silently rewriting Creed / North Stars of other products without owner answers
- Calling a pack “complete” or 🚀 published at v0.x
- Deleting sibling Workspace skill folders until installs point here

## Philosophical done

Every intended pack is **✅ v1** (two solid dogfoods, rubric usable cold) with clear install paths — then selectively **🚀** to skills.sh. The monorepo feels trustworthy because agents can open any pack and run it without undocumented judgment.

## Broken pattern this replaces

Agents invent structure from vibes each session; “skills” that are untested prompt paste; extraction that never leaves the source product.

## Conflict rule

**This North Star > KICKOFF state notes > pack READMEs > tickets > vibes.**

When a ticket or KICKOFF “next” line contradicts these laws, fix the ticket/KICKOFF — do not quietly weaken the laws.

## Decision checklist (any new pack or pack change)

1. Is this a *methodology* (judgment) or a one-off product patch?
2. Does it mirror `linear-methodology/` shape?
3. What’s the first non-extraction-source dogfood target?
4. Does Linear already track it (search-before-create)?
5. Would publishing this at v0.x lie about readiness?
6. If AI writes user data in the *target product*, does `accept-gated-ai` apply — or is this coding-agent / PR territory?

## Drift cadence

Re-read at each pack ✅ v1 and before any 🚀 publish. Suggest a drift audit when a milestone/pack closes.
